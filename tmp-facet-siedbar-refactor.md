## Current sidebar features

### 1. Sort selector
- Partial: app/views/search/common/_sort_by.html.erb
- UI: select dropdown with sort options.
- Current submission method: JavaScript URL mutation + navigation (`Index.applySorting()` -> `Index.setParam('sort', ...)`).
- Not currently `link_to`.

### 2. Clear filters
- Partial: app/views/search/common/_facet_sidebar.html.erb
- Visible only when `@facet_params.present?`.
- Current submission method: `link_to clear_filters_path`.
- Behavior:
  - Removes all search/facet keys and `page`.
  - Preserves unrelated params (for example tab/hash independent behavior).

### 3. Regular facet groups (multi-select values)
- Partial: app/views/search/common/_facet_sidebar_filter.html.erb
- Data source: `available_facets(resources)`.
- Behavior:
  - Active values shown first and marked active.
  - Active values use remove links.
  - Inactive values use add links.
  - Values with blank value or count < 1 are skipped.
  - Start facet is excluded from this loop (`start` handled separately).
- Current submission method: `filter_link` and `remove_filter_link` (`link_to ...` GET URLs).

### 4. Boolean facets/toggles
- Partial: app/views/search/common/_facet_sidebar_boolean_filter.html.erb
- Includes facets from SOLR (`online`) and synthetic booleans (see below).
- Behavior:
  - If active, renders remove link around checked toggle.
  - If inactive, renders add link around unchecked toggle.
  - Uses string `'true'` as value.
- Current submission method: `filter_link` / `remove_filter_link` (`link_to` GET URLs).

### 5. Date range facet (`start`)
- Partial: app/views/search/common/_facet_sidebar_date_filter.html.erb
- UI: lower/upper bound date inputs.
- Current submission method: JavaScript URL mutation + navigation (`Index.applyDateParam`).
- Special behavior:
  - If `start` value becomes `'/'`, JS removes `start` param.

### 6. Max age facet (`max_age`)
- Partial: app/views/search/common/_facet_sidebar_max_age.html.erb
- Values from `Subscription::FREQUENCY`.
- Single-select replacement behavior via `replace: true`.
- Current submission method: `filter_link` / `remove_filter_link` (`link_to` GET URLs).

### 7. Curation section (role-gated)
- Partial: app/views/search/common/_facet_sidebar_curation.html.erb
- Visible only for curator/admin users.
- Supports:
  - `days_since_scrape` (single-select, `replace: true`) via links.
  - `include_hidden` boolean toggle via links.

### 8. Synthetic facet toggles by resource type/feature flags
Defined in app/views/search/common/_facet_sidebar.html.erb using the boolean partial.

Possible toggles:
- `across_all_spaces` (if spaces feature enabled)
- Events:
  - `include_expired`
  - `include_disabled` (unless visibility feature disabled)
  - `include_broken_links`
- Materials:
  - `include_disabled` (unless visibility feature disabled)
  - `include_broken_links`
- Materials and LearningPaths:
  - `include_archived`

All currently use `filter_link` / `remove_filter_link` (GET links).

### 9. Expand/collapse and show-more UI
- Script: app/assets/javascripts/filters.js
- Behavior:
  - Category expand/collapse.
  - "Show N more" paging of facet values.
- Purely presentational; does not submit params itself.

## All current GET link submission points to cover in refactor

These are places where interaction currently submits by navigating to a URL with GET params generated by `link_to`.

1. app/views/search/common/_facet_sidebar.html.erb
- Clear filters button (`link_to clear_filters_path`).

2. app/views/search/common/_facet_sidebar_filter.html.erb
- Add regular facet value (`filter_link`).
- Remove active regular facet value (`remove_filter_link`).

3. app/views/search/common/_facet_sidebar_boolean_filter.html.erb
- Enable boolean facet (`filter_link(facet_field, 'true', ...)`).
- Disable boolean facet (`remove_filter_link(facet_field, 'true')`).

4. app/views/search/common/_facet_sidebar_max_age.html.erb
- Set max_age (`filter_link(..., replace: true)`).
- Unset max_age (`remove_filter_link(..., replace: true)`).

5. app/views/search/common/_facet_sidebar_curation.html.erb
- Set days_since_scrape (`filter_link(..., replace: true)`).
- Unset days_since_scrape (`remove_filter_link(..., replace: true)`).
- Include hidden toggle add/remove via boolean partial link helpers.

6. app/views/search/common/_search_filters.html.erb (outside sidebar, but same facet/query state)
- Remove active facet chips (`remove_filter_link`).
- Remove query chip (`remove_filter_link('q', params[:q], ...)`).

Note: the `_search_filters` chips are not inside the sidebar but represent the same filter state. If your refactor changes parameter conventions, chip removal must still work.

## Parameter semantics to preserve (important)

From app/helpers/search_helper.rb:

### `filter_link`
- Starts from `search_and_facet_params` (permitted search/facet params only).
- If key already exists and `replace` is not set:
  - converts existing value to array and unions with new value (no duplicates).
- If `replace: true`:
  - sets/replaces existing value directly.
- Deletes `page` before navigating.

### `remove_filter_link`
- Starts from `search_and_facet_params`.
- If key value is array:
  - removes only clicked value.
  - if one value remains, converts array back to singleton.
- If key value is singleton:
  - removes entire key.
- Deletes `page`.

### `clear_filters_path`
- Uses full params and removes all model `search_and_facet_keys` + `page`.
- Keeps unrelated params.

## Non-link param submissions related to sidebar UX

Not `link_to`, but still part of current filtering/sorting behavior:

1. app/views/search/common/_sort_by.html.erb
- `Index.applySorting()` updates `sort` query param and navigates.

2. app/views/search/common/_facet_sidebar_date_filter.html.erb

## Suggested self-check list for your form-based refactor

When you are done, verify each item:

- [ ] Every former `filter_link` add action works via GET form submit.
- [ ] Every former `remove_filter_link` action works via GET form submit.
- [ ] Removing one value from a multi-value facet preserves remaining values.
- [ ] Single-value facets with previous `replace: true` still replace (not append).
- [ ] `page` resets on every facet/sort/filter mutation action.
- [ ] Clear filters still preserves unrelated non-search params.
- [ ] Boolean toggles still map to `'true'` when enabled.
- [ ] Date range (`start`) update/remove semantics remain unchanged.
- [ ] Max age and curation days filters still behave as single-select.
- [ ] Curation-only section remains role-gated.
- [ ] Feature-flag/resource-type conditional toggles remain unchanged.
- [ ] Search filter chips in `_search_filters` still correctly remove facets/query.
- [ ] Show-more and expand/collapse JS still works with new markup.

## Notes specifically for your intended approach

If you use:
- readonly inputs for selected facets,
- submit buttons for selectable facets,
- submit buttons for deleting selected facets,
- JS disabling of the corresponding input before submit,

then also verify:
- [ ] Input names exactly match existing params expected by controller/model (`@model.facet_keys_with_multiple`, `search_and_facet_keys`).
- [ ] Multi-value facet fields submit as arrays where needed.
